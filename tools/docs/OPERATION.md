## 同期のしくみと3つのきっかけ

**同期**とは、`items/` の作品フォルダを読んで、スプシ（シート `items`）を最新の写しにする処理です。フォルダごとに「ファイルの名前・サイズ・更新日時」から指紋（fingerprint）を作り、前回と同じならそのフォルダは読み直さず、違えば `meta.json` を読み直して行を更新します。写真を1枚足しただけでも拾えます。`items/` から消えた（ゴミ箱に入れた・先頭を `_` にした）フォルダの行は、全件を見終えた回に削除されます。

| きっかけ | 誰が | 備考 |
| --- | --- | --- |
| **毎日の自動同期** | 時間トリガー（毎日4時台のどこか） | `setup()` で登録される。何もしなくてよい |
| **スプシのメニュー「ギャラリー → 今すぐ同期」** | スプシの編集権限のある人 | 結果は画面右下の通知に出る。時間切れなら続きを自動で再開する |
| **ギャラリー画面の「今すぐ同期」ボタン**（と、詳細の「この作品だけ再同期」） | スプシの編集権限がある人（`items/` は閲覧できれば足りる） | 編集権限が無い人は、同期の前の確認ですぐ「同期にはスプシの編集権限が必要です（items フォルダは閲覧できれば足ります）」と出る。画面ではボタン自体が押せない表示になる |

「この作品だけ再同期」（詳細の下、および要対応の各行の「再同期」ボタン）は、指紋に関係なくその1件の `meta.json` を読み直します。直した直後に確認したいときに使います。`items/` 直下の一覧に無い（フォルダが無い・ゴミ箱の中・先頭が `_`・`items/` の外に移された）場合は、その行を一覧から外します。

同期は `*.tmp` のファイル（Fusion書き出しの一時ファイルなど）を無視します。

### 時間切れのときの挙動

GASの1回の実行は最大6分です。同期は約4.5分で区切り、そこまでの結果をシートに書いて、**どこまで進んだかを保存**します（フォルダ名順に処理します）。

- **自動同期・スプシのメニュー**：続きを**1分後に自動で再開**します（1回限りのトリガーを作り、実行後に自分で消えます）。「途中まで同期しました…続きは1分ほどで自動的に再開します」と表示されます。
- **画面のボタン**：続きのトリガーは作りません（閲覧者のアカウントにトリガーが残らないようにするため）。「途中まで同期しました…もう一度押すと続きから再開します」と出るので、もう一度押してください。
- 途中の回では、消えたフォルダの行の削除は行いません（まだ見ていないだけの行を消さないため）。
- **一覧が欠けたときの安全装置**：全件を見終えた回に、次のどちらかなら行の削除を**見送り**、メッセージを出します。`ITEMS_FOLDER_ID` の誤りや権限の問題で、一覧が丸ごと消えるのを防ぐためです。
  - `items/` の中でフォルダが1つも見つからないのに、シートに行がある
  - シートに10行以上あり、その半数を超える行を消すことになる
  見送ったときは「最終同期」の時刻も更新されません。`ITEMS_FOLDER_ID` と権限を確認し、本当に消してよいなら「全部作り直す」を使ってください。
- 別の同期が実行中のときは「別の同期が実行中です。少し待ってからもう一度押してください」と出ます。自動同期の場合は何もせず終わり、次の実行で拾います。
- 想定規模（数十〜百数十件）なら、通常は1回で終わります。

ギャラリー上部の「最終同期」は、**全件を見終えた最後の時刻**です。途中までの回では更新されません。

## エラー（要対応）の見方と直し方

作品フォルダに不備があると、その作品はギャラリーの一覧に**出ません**。代わりに、一覧の最上部に「**一覧に出ていない作品がN件あります**」というバーが出て、作品ごとに理由が並びます（この文書では「要対応」と呼びます）。各行から「Driveのフォルダ」と「スプシの該当行」へ飛べます。スプシでは `error` 列に同じ内容が入っています（複数あるときは ` / ` でつながります）。

**直し方の基本**：フォルダ名か `meta.json` を直して、ギャラリーの「今すぐ同期」（または詳細の「この作品だけ再同期」）を押す。要対応が0件になれば完了です。

### エラーメッセージ一覧

| メッセージ | 原因 | 直し方 |
| --- | --- | --- |
| フォルダ名が「YYYYMMDD_名前」の形式ではありません | 先頭が8桁の数字＋`_`になっていない | `20250612_流路セルホルダー` の形に改名する |
| フォルダ名の日付「XXXXXXXX」は実在しない日付です | 20250231 など、カレンダーに無い日付 | 実在する日付に直す（不明なら大体でよい） |
| meta.json がありません | フォルダ直下に `meta.json` が無い（サブフォルダの中は不可） | `_template/meta.json` をコピーして置く |
| meta.json が○個あります（1つにしてください） | 同名ファイルが複数ある（Driveは同名を許す） | 余分なものを消す |
| ファイルが多すぎて一覧を保存できません（○個）。フォルダを分けてください | ファイル一覧のJSONがスプシの1セルの上限（50000文字）を超える | フォルダ内のファイルを減らす（作品を分ける） |
| 「○○」が長すぎるため切り詰めました（50000文字まで） | `note` などが1セルの上限を超える | 内容を短くする。切り詰めた状態で要対応になる |
| meta.json を読めません（…） | ファイルの読み取りに失敗 | ファイルが開けるか確認し、作り直して置き直す |
| meta.json を JSON として読めません（カンマや " の過不足を確認してください） | JSONの書式エラー | 最後の項目の後ろの余分なカンマ、`"` の閉じ忘れ、全角の `"` を確認する。JSON検証サイトに貼ると場所がわかる |
| meta.json の中身が { } で囲まれていません | 配列や文字列だけが書かれている | 全体を `{ … }` にする |
| meta.json に「author」がありません（purpose / status も同様） | 必須キーが無い | キーを足す |
| 「author」は文字列で書いてください（purpose / status も同様） | 数値や配列などが入っている | `"山田"` のように `" "` で囲む |
| 「author」が空です（purpose / status も同様） | 空文字や空白だけ | 内容を書く。Fusion書き出し直後の雛形はこの状態（**未記入の作品**） |
| 「status」は 使用中 / 参考 / 引退 のどれかにしてください（今は「…」） | 選択肢以外の文字 | 3つのどれかに直す（表記ゆれ・全角半角に注意） |
| 「tags」は文字列の配列で書いてください（例: ["顕微鏡", "治具"]） | `"tags": "顕微鏡"` のように配列でない | `["顕微鏡"]` にする |
| 「note」は文字列か、文字列の配列で書いてください | 数値やオブジェクトが入っている | 文字列、または文字列の配列にする |

`meta.json` を書くときの注意：

- 未知のキーはエラーになりません（無視されます）。
- UTF-8 で保存してください。Windowsのメモ帳が付ける先頭の BOM は自動で除かれます。
- `tags` と `note` は書かなくてもかまいません。

### 画面に出る「同期できませんでした」の類

| 表示 | 原因と対処 |
| --- | --- |
| スクリプトプロパティ「ITEMS_FOLDER_ID」が設定されていません | [SETUP.md の手順5](SETUP.md#5-スクリプトプロパティ-items_folder_id-を設定する) |
| items フォルダ（ID: …）を開けません | IDの誤り、または権限不足 |
| 同期にはスプシの編集権限が必要です（items フォルダは閲覧できれば足ります） | 押した人にスプシの編集権限が無い。研究室のメンバーなら編集者に追加する（全員を編集者にする方針。[権限の管理](#権限の管理)）。外部の人なら、毎日の自動同期を待ってもらう |
| 一覧を読み込めません。スプシを閲覧する権限があるか確認してください | 画面を開いた人にスプシの閲覧権限が無い。スプシ（共有ドライブ）に追加する |
| 一覧を読み込めませんでした：… | 一覧の読み込みの想定外のエラー |
| items フォルダの中が見つからないため、行の削除を見送りました。… | 安全装置（上記）。`ITEMS_FOLDER_ID` と権限を確認 |
| 消えたフォルダが多すぎるため、行の削除を見送りました（○行）。… | 安全装置（上記）。問題なければ「全部作り直す」 |
| 同期に失敗しました：… | 想定外のエラー。時間をおいて再実行し、続く場合は改修できる人へ（実行ログはApps Scriptエディタの「実行数」で見られる） |

画像だけ出ない（形のアイコンになる）場合は、閲覧者のDrive権限か、ブラウザのCookie設定が原因のことがあります。動作には影響しません。

## 「全部作り直す」を使う場面

スプシのメニュー「**ギャラリー → 全部作り直す**」は、シートのデータ行を消して、`items/` から全件を読み直します（確認ダイアログが出ます）。普通の同期は変化したフォルダしか読まないので、次のような「シートの状態がおかしい」ときに使います。

- 誰かがスプシを手で編集してしまい、元に戻らない
- シートの行を誤って消した、並べ替えた
- 安全装置で行の削除が見送られたが、本当に消してよい場合
- 見出しや列の順番が違っている（`HEADERS` を変えた改修のあとなど）
- 原因不明で、画面とフォルダの内容が合わない

注意：

- 件数が多くて時間切れになると、そこまで読めた分だけがシートに載り、残りは続きの同期（約1分後に自動）で入ります。その間、ギャラリーには一部の作品しか出ません。しばらく待ってください。
- 元データは `items/` なので、作り直しで作品が失われることはありません。

## 権限の管理

**研究室のメンバーは全員、スプシの編集者にします**（権限の管理を続けなくて済むように。2026-10-30 決定）。新しいメンバーが来たら、共有ドライブ（またはスプシ）に編集者として追加してください。研究室の外の人は閲覧者にします。

知っておくこと：スプシ（＝Apps Scriptのコード）の**編集者は、コードを書き換えられ、そのコードはギャラリーを開いた人の権限で動きます**。全員が研究室のメンバーなのでこれを受け入れています。Webアプリが求める許可は `appsscript.json` でDriveの「閲覧のみ」などに絞ってあります（[SETUP.md](SETUP.md#4つ目appsscriptjson-を置き換える許可の範囲を絞る)）。Apps Script のコードは、改修する人以外は触らないでください。

## スプシを手で編集しない理由

スプシは `items/` の**写し**で、同期のたびに上書きされるからです。スプシで直しても、次の同期で消えます。直したい内容は、**各作品フォルダの `meta.json`**（とフォルダ名）を直して同期してください。シートには「警告のみ」の保護がかかっていて、編集しようとすると警告が出ます（同期を止めないため、完全には禁止していません）。

## 管理者交代時の手順

構築者・管理者が卒業するときは、必ず**在籍中に**引き継ぎます。理由：毎日の自動同期の**トリガーは、作った人のアカウントで動く**ため、そのアカウントが無効になると止まります。新しい管理者が作り直す必要があります。旧管理者がまだ在籍しているうちに、次の順で行います。

1. **共有ドライブの管理者に新管理者を追加する**（旧管理者または他の管理者が実施）。`3Dギャラリー/` とスプシ（Apps Script を含む）を編集できる状態にする。卒業する人は、共有ドライブのメンバーから外す（卒業時）。
2. **新管理者がスプシを開き、「拡張機能 → Apps Script」が開ける**ことを確認する。
3. **新管理者が `setup()` を実行する**（スプシのメニュー「ギャラリー → 初期設定」、またはエディタで `setup` を実行）。許可画面が出たら許可する。これで**新管理者のアカウントで**毎日の同期トリガーが登録される。結果に「毎日の同期：登録しました」と出ることを確認する。
   - `setup()` は、実行した人のトリガーしか見ません。旧管理者のトリガーが残っていても、新管理者側には新しく登録されます。
4. **旧管理者のトリガーを削除する**。旧管理者が Apps Script エディタ左の時計マーク「トリガー」を開き、`dailySync`（と、残っていれば `continueSync`）を削除する。削除しないと新旧で2本動きます（同期はロックで二重実行が防がれるので壊れはしませんが、無駄です）。旧管理者のアカウントが先に無効になった場合は、そのトリガーも動かなくなるので、この手順は不要です。
5. **デプロイを確認する**。`appsscript.json`（許可の範囲と実行ユーザー）が変わっていないことも確認する。新管理者が「デプロイ → デプロイを管理」で既存のデプロイを開けることを確認する。今後コードを変えるときは、「新しいデプロイ」ではなく**既存のデプロイを編集して「新バージョン」を出す**（URLが変わらない。[SETUP.md](SETUP.md#更新するとき新しいデプロイとデプロイを管理の違い)）。実行ユーザーは「ウェブアプリにアクセスしているユーザー」なので、旧管理者が卒業しても、閲覧する人の権限で動き続けます。
6. **動作確認**：新管理者がスプシのメニュー「今すぐ同期」とギャラリーのURLを確認する。翌日、エディタの「実行数」に、新管理者のアカウントで `dailySync` が走った記録があることを確認する。
7. **置き場所を確認する**：`3Dギャラリー/` が共有ドライブにあること（マイドライブでないこと）、`tools/` の控えが最新であること、[README.md](README.md) のURLが正しいこと。

データ（`items/`、スプシ、コード）が共有ドライブにあれば、管理者が替わっても失われるものはありません。

## Fusion書き出しの運用

Fusionのクラウドにある f3d を、まとめて `items/` 用の作品フォルダとして書き出すスクリプト `tools/fusion_export/fusion_export.py` の使い方です。**卒業でAutodeskアカウントやFusionのライセンスを失うと、クラウド上のf3dに二度とアクセスできなくなるため、在籍中に回収するのが最優先です。**

流れ：**モード1（サムネイルだけ撮って一覧を作る）→ 人が仕分け → モード2（フル書き出し）**。

### 準備

1. `tools/fusion_export/` フォルダ（`fusion_export.py` と `fusion_export.manifest` が入っている）を、手元のPCにコピーする。
2. Fusionを起動し、「ユーティリティ」タブの「**スクリプトとアドイン**」を開く（Shift+S）。「スクリプト」タブの「＋」から、コピーした `fusion_export` フォルダを選んで登録する。
3. 冒頭の「**設定欄**」を書き換える（`fusion_export.py` をエディタで開いて保存すればよい）。

設定欄は「**共通 → モード1だけ → モード2だけ → 細かい設定**」の順に並んでいます。パスは `r"..."` の `""` の中に書きます。**先頭の `r` は消さないでください**（`r` が無いと `\` のあとの文字が化けて、別の場所を指します。化けたときは実行の最初に止まって知らせます）。

| 区分 | 設定 | 意味 |
| --- | --- | --- |
| 共通 | `MODE` | 1 = サムネイルのみ、2 = フル書き出し |
| 共通 | `PROJECT_NAMES` | 対象のFusionプロジェクト名のリスト。`[]` なら全部。**今選んでいるチーム（データパネル左上のハブ）の中だけ**が対象。1つだけなら `"研究室共有"` のように文字列で書いてもよい |
| 共通 | `TARGET_NAMES` | 扱うファイルをFusion上の名前で絞るリスト。`[]` なら全部（使い方は下の「一部のファイルだけ扱う」） |
| モード1だけ | `TRIAGE_DIR` | モード1の出力先。`triage.csv` と画像が入る。**初期値は空 `r""` で、空ならこのPCの `ドキュメント\3Dギャラリー_仕分け`**（仕分けの作業用なので共有しなくてよい。書き換えなくてよい）。「ドキュメント」はエクスプローラーの「ドキュメント」と同じ場所で、OneDrive に移している PC ではその移した先になります。**実際の場所は、終了時のダイアログの「一覧」で確認してください**。共有ドライブに置きたければ書き換えてよいが、`items` の**外**にする（中だと作品フォルダと間違えて同期されるため） |
| モード2だけ | `TRIAGE_CSV` | モード2で読む `triage.csv` のパス。**初期値は空**で、空なら `TRIAGE_DIR` の中の `triage.csv` を読む（ふつうはこのままでよい）。スプシで編集して別の場所に保存したときだけ、そのパスを書く |
| モード2だけ | `OUTPUT_DIR` | モード2の出力先。Google ドライブ（パソコン版）で見える共有ドライブ内の `3Dギャラリー/items`。**初期値は `G:\共有ドライブ\<共有ドライブ名>\3Dギャラリー\items`。`<共有ドライブ名>` を実際の名前に書き換える（`< >` ごと消す）。ドライブ文字（`G:`）はPCによって違う**（エクスプローラーでそのフォルダを開いて、アドレスバーのパスを使う）。`< >` が残っていると実行は止まります。**書き換えが必要なのは、設定欄の中でここだけ**です |
| モード2だけ | `DEFAULT_AUTHOR` / `DEFAULT_STATUS` / `DEFAULT_TAGS` | 書き出す `meta.json` に最初から入れておく値（全作品に同じ値が入る。既定は空）。例：`"山田"` / `"使用中"` / `["治具", "PLA"]`。`DEFAULT_STATUS` は `使用中` / `参考` / `引退` のどれか（ほかの値だと同期で要対応になる）。`purpose` は作品ごとに違うので既定値はありません |
| 細かい設定 | `STL_PER_BODY` | `True` = ボディごとにSTL（1部品だけ刷り直せる）。`False` = 1ファイルにまとめる |
| 細かい設定 | `MESH_QUALITY` | `"high"` / `"medium"` / `"low"`（STL・3MFの細かさ） |
| 細かい設定 | `THUMB_WIDTH` / `THUMB_HEIGHT` | サムネイルの大きさ（初期値 1200×800） |

ふつうは、モード1では**何も書き換えずに**そのまま実行できます（必要なら `PROJECT_NAMES` だけ）。モード2では `OUTPUT_DIR` の `<共有ドライブ名>` を書き換え、必要なら `DEFAULT_*` を埋めます。

Windowsのパスは `r"…"` で囲んだままにしてください。設定を保存して、スクリプトを選び「実行」を押します。

実行中の注意：Fusion本体を起動してその中から実行します（裏では動かせません）。1件ずつクラウドから開くので、件数が多いと時間がかかります。進捗ダイアログに「中止」ボタンがあります。実行中は他の操作を控えてください。

### モード1：サムネイルのみ

1. `MODE = 1` にして実行する（`PROJECT_NAMES` で対象を絞りたいときだけ設定する。`TRIAGE_DIR` は既定のままでよい）。
   - **`triage.csv` を Excel などで開いたままにしない**でください。開いていると書き換えられないため、撮影を始める前に「Excel などで開いていたら閉じてください」と出て止まります（閉じてから実行し直す）。撮影の途中で開いて、最後に `triage.csv` を書けなかったときは、結果を `triage_new_日時.csv` に書き、ダイアログで案内します。そのときは `triage.csv` を閉じ、元の `triage.csv` を消すか別名にしてから、`triage_new_日時.csv` の名前を `triage.csv` に変えてください。
2. 完了のダイアログに、保存した画像の数・失敗した数・一覧の場所が出る。`TRIAGE_DIR`（既定は `ドキュメント\3Dギャラリー_仕分け`。実際の場所はダイアログの「一覧」で確認）に次ができる。
   - `triage.csv`：一覧
   - `<フォルダ名案>.png`：サムネイル画像
   - `export_log.csv`：ログ
3. **仕分け**：`triage.csv` をスプシ（Excelでも可）で開き、画像を見ながら `rank` 列に **A / B / C** を書く。必要なら `folder_name`（`YYYYMMDD_名前` の案が最初から入っている）を直す。
   - A：研究室で現役の部品（写真・noteを丁寧に）／B：参考になる過去作／C：失敗作・一発ネタ（登録しない）。**`rank` が A か B の行だけが書き出されます。**
   - `folder_name` の日付が `00000000` の行は、作成日が取れなかったものです。実在する日付に直してください（直さないと同期でエラーになります）。
4. CSVで保存する。Excelなら、そのまま同じ `triage.csv` に上書き保存してよい（Shift_JIS でも読めます）。スプシで編集したなら「ファイル → ダウンロード → カンマ区切りの値（.csv）」で保存し、`TRIAGE_DIR` の `triage.csv` と置き換える（別の場所に置くなら、そのパスを `TRIAGE_CSV` に書く）。

`triage.csv` の列：`project`（プロジェクト）、`folder_path`、`name`（Fusion上の名前）、`datafile_id`、`version_id`、`created`、`modified`、`image`、`rank`、`folder_name`。

**モード1を再実行しても、記入済みの `rank` と `folder_name` は消えません。** 既存の `triage.csv` は `triage_日時.csv` に退避（バックアップ）されたうえで、新しい `triage.csv` には `datafile_id` が同じ行の `rank` と `folder_name` が引き継がれます。今回撮らなかった行や、Fusionから消えたファイルの行もそのまま残り、新しく増えたファイルは最後に足されます。そのため、ファイルを足したあとの撮り直しや、一部だけの撮り直し（下の「一部のファイルだけ扱う」）をしても、仕分けをやり直す必要はありません。

**第1版から移る人への注意**：第1版では `TRIAGE_DIR` の既定が共有ドライブ上でした。そこにある `triage.csv` に `rank` を記入済みなら、そのままモード1を実行すると、新しい既定の場所（`ドキュメント\3Dギャラリー_仕分け`）に**空の `rank` の一覧が新しく作られ、記入済みの仕分けが引き継がれません**。次のどちらかをしてから実行してください。

- `TRIAGE_DIR` に、記入済みの `triage.csv` があるフォルダ（第1版のときの場所）を書く。
- 記入済みの `triage.csv` を、新しい既定の場所（`ドキュメント\3Dギャラリー_仕分け`。無ければ作る）に移す。画像も使うなら一緒に移す。

どちらでも、そのあとモード1を実行し直せば、記入済みの `rank` と `folder_name` が引き継がれます。

### モード2：フル書き出し

1. `MODE = 2` にし、`OUTPUT_DIR` の `<共有ドライブ名>` を書き換える（`DEFAULT_*` を使うならそれも）。`TRIAGE_CSV` は空のままなら `TRIAGE_DIR` の `triage.csv` を読む。実行する。
2. `rank` が A か B の行ごとに、`OUTPUT_DIR/<folder_name>/` を作り、次を書き出す。

   | 出力 | 内容 |
   | --- | --- |
   | `<名前>.f3d` | Fusionの元データ |
   | `<名前>.step` | STEP |
   | `<コンポーネント名>_<ボディ名>.stl` | ボディごと（`STL_PER_BODY = True` の場合）。ルート直下のボディはボディ名のみ。名前が重なれば `_2` など |
   | `<名前>.3mf` | 3MF |
   | `thumb.png` | ギャラリーの代表画像 |
   | `meta.json` | 雛形（`author` `status` `tags` は `DEFAULT_*` の値、`purpose` は空、`note` は空）。済み判定用の `fusion_id` が入る（下記） |

   `OUTPUT_DIR` がDriveの `items/` なら、書き出し＝登録です。
3. 完了ダイアログに、成功・成功（要目視確認）・失敗・スキップの件数とログの場所が出る。スキップは「書き出し済み」と「fusion_id なし・未確認」に分けて出ます。「未確認」が1件以上あれば、ログの「スキップ」の行を見て対処してください（下の `export_log.csv` の表）。
   - 書き出しの途中、作品フォルダに目印 `fusion_id.tmp` ができます。完了すると消えます（残っていてもギャラリーには出ず、害はありません）。消さないでください（途中で止まったフォルダがどの作品のものかを、次の実行で見分けるのに使います）。
4. 各作品の `meta.json` を埋める（手で、またはギャラリーの「作品を追加する」のAIの方法）。**`fusion_id` の行は消さない・書き換えない**でください（書き出し済みかの判定に使う印です。下の「再実行の挙動」）。`fusion_id` はギャラリーの画面には出ません。
5. ギャラリーの「今すぐ同期」を押す。`meta.json` が空の作品は「`author` が空です」などで要対応に出ます（**未記入の作品**）。要対応が0件になれば完了です。

### 一部のファイルだけ扱う（`TARGET_NAMES`）

`TARGET_NAMES` にFusion上のファイル名を書くと、その名前のファイルだけを扱います。例：`TARGET_NAMES = ["流路セルホルダー", "顕微鏡ステージ"]`。空の `[]` なら全部です。1つだけなら `TARGET_NAMES = "流路セルホルダー"` のように文字列で書いても、その名前1つとして扱います。

- 名前は**完全一致**です（前後の空白は無視。濁点の表し方の違いはそろえて比べます）。同じ名前のファイルが複数あれば全部が対象です。モード2で、指定した名前の行が `triage.csv` に複数（別のプロジェクトやフォルダの同名ファイル）あるときは、全部を書き出し、`export_log.csv` に「注意」を出します。そのうち1つだけにしたいときは、`TARGET_NAMES` を `[]` に戻し、`rank` で選んでください（書き出したい行だけ A か B にする）。
- **モード1**：指定した名前のファイルだけ画像を撮り直します。`triage.csv` のほかの行はそのまま残り、撮り直した行は `rank` と `folder_name` を引き継ぎます。
- **モード2**：`triage.csv` の中から、指定した名前の行だけを書き出します。**`rank` は問いません**（空や C でも書き出す。名前を書いたことが「書き出す」という指示になるため）。
- 見つからなかった名前は、最後のダイアログと `export_log.csv`（注意）に出ます。打ち間違いに気づけます。
- 全部に戻すときは `[]` にします。

### `export_log.csv` の見方

モード1は `TRIAGE_DIR` に、モード2は `OUTPUT_DIR`（`items/` の直下）に作られます。`items/` 直下のファイルは同期の対象ではない（同期が読むのはフォルダだけ）ので、置いたままで問題ありません。1件ごとに追記され、途中でFusionが落ちてもそこまでは残ります。列は `time, mode, name, result, detail` です。

| result | 意味 | 対応 |
| --- | --- | --- |
| 成功 | 書き出し完了（`meta.json` まで書けた）。外部参照があっても、全部取り込めたときは「外部参照 N 件を取り込んで f3d を書き出し」と付いて成功になる | `detail` の「取得: version_id」などは、ファイルをどのIDで見つけたかの記録（`version_id` → `datafile_id` → プロジェクトの再走査の順。古い版で見つかったときは最新版に替え「→最新版」と付く）。通常は気にしなくてよい。「開いていたドキュメントに未保存の変更があり、その状態で書き出しました」とあれば、保存前の状態が出ているので確認する |
| 成功（要目視確認） | 書き出せたが、**外部参照を含む**デザイン（他のデザインを参照するアセンブリ）で、f3d に参照先が入っていない可能性がある。次のどれか：元々Fusionで開いていたドキュメントだった（取り込まずに書き出した）／取り込めなかった部品が残った／取り込める部品が見つからなかった。`detail` に「外部参照あり」など | f3d をFusionで開き、部品が入っているか目視で確認する（STEP・STL・3MFは参照先ごと出ています） |
| 失敗 | 開けない、書き出し形式のどれかが失敗、など。`detail` に原因 | 原因を直して再実行（下記）。その作品フォルダには `meta.json` が書かれない |
| スキップ（書き出し済み） | 出力先フォルダの `meta.json` の `fusion_id` が、この作品と一致する（書き出し済み）ので飛ばした。`detail` は「meta.json があり、同じ作品のため（書き出し済み）」 | 何もしなくてよい。書き出し直したいときは、作品フォルダを消してから再実行（下の「再実行の挙動」） |
| スキップ（fusion_id なし・未確認） | 出力先に同名のフォルダがあり、その `meta.json` に `fusion_id` が無い（消した・手作り・旧版の出力）ので、同じ作品か確かめられないまま念のため飛ばした。旧版の出力で「Fusion元」の場所が今回の行と違う場合もここ（Fusionで名前や場所を変えただけかもしれないため）。`detail` は「fusion_id が無いため念のためスキップ（…）」。終了時のダイアログでは「スキップ（fusion_id なし・未確認）」に数える | **同じ作品なら**：`meta.json` に `fusion_id` を戻す（済みとして扱われる）か、作品フォルダを消してから再実行（書き出し直す）。**別の作品なら**：`triage.csv` のこの行の `folder_name` を別の名前に変えて再実行 |
| 注意 | `triage.csv` の `folder_name` に問題（CSV内の重複を `-v2` などに変更した、形式外の名前）、または**同名の別作品のフォルダが既にあるため `-v2` などに書き出した**（`fusion_id` が違うとき。済みで飛ばすときは出ない）。`datafile_id` が空の行は書き出さずに、この「注意」を出す。`TARGET_NAMES` の名前の行が `triage.csv` に複数あるときも出す。作品名の欄は空のことがある | 該当の `folder_name` を直す。別作品の同名フォルダが手作りのものなら意図どおりか確認する |

ログの `result` 欄の語は、どちらのスキップも「スキップ」です（`detail` で見分けます）。

`detail` には「表示中のソリッドボディが無いため STL/3MF なし」のような補足も入ります。モード1のログは、画像を保存できたか（成功）か、開けなかった（失敗）かを記録します。

### 外部参照のあるデザイン

他のデザインを部品として挿入している（**外部参照**）デザインは、Fusionの API では参照先を含む形で f3d を書き出せず、**そのまま書き出すと f3d の中身が空になります**（実機で確認）。そこでスクリプトは、**自分で開いたデザインに限り**、外部参照の部品を `breakLink`（取り込み）でそのデザインの中の部品にしてから f3d を書き出します。

- **保存はしません**。書き出したあと保存せずに閉じるので、Fusionのクラウド上の元データは変わりません。
- 書き出しの順は **STEP → STL → 3MF → サムネイル → 取り込み → f3d**。STEP・STL・3MF・サムネイルは、取り込まなくても参照先ごと出ます。取り込みを最後にすることで、取り込みに失敗してもそれらが無事に残ります。
- 元々Fusionで開いていたデザインは書き換えないので、取り込まずに書き出し、ログを「成功（要目視確認）」にします（f3d に参照先が入っていない可能性）。
- ログの判定は、全部取り込めれば「成功」、取り込めなかった部品が残る・取り込める部品が無いのに外部参照の印がある・元々開いていた、のいずれかなら「成功（要目視確認）」です。
- 既知の制約：API では、参照先を含む本物の f3z は作れません。取り込んだ f3d は、参照先が単体の部品として入った形になり、元のデザインとの参照のつながりは切れます。つながりを残したい作品は、Fusionの画面から f3z で書き出してください。

### 再実行の挙動

- **書き出し済みかは、出力先フォルダの `meta.json` の `fusion_id` で判断します**。`fusion_id` は書き出し時にスクリプトが入れる、Fusion上のファイルの固有のIDです（名前を変えたり、フォルダを移したり、保存し直したりしても変わりません）。この作品の `fusion_id` と一致すれば済みとして飛ばします（`meta.json` を人が埋めたあとでも、この行を消さなければ飛ばされます）。`meta.json` は全部の書き出しが成功したときに**最後に**書くので、途中で止まったフォルダ（`meta.json` が無い）は次の実行でやり直されます。
- **`meta.json` の `fusion_id` は消さない・書き換えない**でください。消すと、念のため「済み」として飛ばされます（「スキップ（fusion_id なし・未確認）」のまま、書き出し直されません）。書き換えると、別の作品とみなされて `-v2` のフォルダに書き出されます。ギャラリーの画面には出ないので、見た目では気づけません。
- **同名のフォルダが別の作品のとき**（`fusion_id` が違う、または読めない `meta.json`）は、上書きせず `-v2`、`-v3` … の空き名に書き出し、ログに「注意」を残します。手作りのフォルダや旧版の出力で `fusion_id` が無い場合は、同じ作品かどうか分からないため、念のため飛ばします（ログに理由と対処が出ます）。
- `-v2` などの番号は、再実行しても変わりません。番号を選ぶとき、出力先にある同名の候補（`-v2`、`-v3` …）を全部調べ、この作品の完了済みのフォルダがあればそれを使います。途中で止まったフォルダは目印 `fusion_id.tmp` で持ち主を見分け、**他の作品の途中のフォルダは取りません**（目印の無い途中のフォルダは、`triage.csv` どおりの名前のときだけ自分のものとして扱います）。
- 失敗した作品は、原因を直して**そのままモード2をもう一度実行**すれば、失敗分だけやり直します。
- **書き出し済みの作品を書き出し直したいときは、その作品フォルダを消してから再実行します**（`TARGET_NAMES` でその作品だけに絞ると早い）。`meta.json` を埋めたあとに消すと記入内容も失われるので、必要なら先に控えを取ってください。
- 同じ `folder_name` が複数あると、2つ目以降に `-v2`、`-v3` を付けます（CSVの行順で振るので、同じCSVなら再実行しても同じ名前になります）。
- 書き出し途中の `items/` では、`meta.json` がまだ無いフォルダが「meta.json がありません」と要対応に出ます。実行が終われば解消します。

### うまくいかないとき

- 開けない・書き出せない作品は、手動（Fusionで開いて「ファイル → エクスポート」）で補い、ギャラリーの「作品を追加する」の手順で置いてください。
- Fusionのバージョンアップでスクリプトが動かなくなることがあります。確認済みのバージョンは [DEVELOPMENT.md](DEVELOPMENT.md#確認したfusionのバージョン) にあります。STEPが残っていれば、Fusionが無くても他のCADで形を取り戻せます。
