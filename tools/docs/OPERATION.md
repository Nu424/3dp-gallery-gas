## 同期のしくみと3つのきっかけ

**同期**とは、`items/` の作品フォルダを読んで、スプシ（シート `items`）を最新の写しにする処理です。フォルダごとに「ファイルの名前・サイズ・更新日時」から指紋（fingerprint）を作り、前回と同じならそのフォルダは読み直さず、違えば `meta.json` を読み直して行を更新します。写真を1枚足しただけでも拾えます。`items/` から消えた（ゴミ箱に入れた・先頭を `_` にした）フォルダの行は、全件を見終えた回に削除されます。

| きっかけ | 誰が | 備考 |
| --- | --- | --- |
| **毎日の自動同期** | 時間トリガー（毎日4時台のどこか） | `setup()` で登録される。何もしなくてよい |
| **スプシのメニュー「ギャラリー → 今すぐ同期」** | スプシを開いた編集権限のある人 | 結果は画面右下の通知に出る。時間切れなら続きを自動で再開する |
| **ギャラリー画面の「今すぐ同期」ボタン**（と、詳細の「この作品だけ再同期」） | スプシと `items/` の編集権限がある人 | 権限が無い人が押すと「同期には items フォルダとスプシの編集権限が必要です」と出る |

「この作品だけ再同期」は、指紋に関係なくその1件の `meta.json` を読み直します。直した直後に確認したいときに使います。フォルダが無い・ゴミ箱の中・先頭が `_`・`items/` の直下にない場合は、その行を一覧から外します。

### 時間切れのときの挙動

GASの1回の実行は最大6分です。同期は約4.5分で区切り、そこまでの結果をシートに書いて、**どこまで進んだかを保存**します（フォルダ名順に処理します）。

- **自動同期・スプシのメニュー**：続きを**1分後に自動で再開**します（1回限りのトリガーを作り、実行後に自分で消えます）。「途中まで同期しました…続きは1分ほどで自動的に再開します」と表示されます。
- **画面のボタン**：続きのトリガーは作りません（閲覧者のアカウントにトリガーが残らないようにするため）。「途中まで同期しました…もう一度押すと続きから再開します」と出るので、もう一度押してください。
- 途中の回では、消えたフォルダの行の削除は行いません（まだ見ていないだけの行を消さないため）。
- 別の同期が実行中のときは「別の同期が実行中です。少し待ってからもう一度押してください」と出ます。自動同期の場合は何もせず終わり、次の実行で拾います。
- 想定規模（数十〜百数十件）なら、通常は1回で終わります。

ギャラリー上部の「最終同期」は、**全件を見終えた最後の時刻**です。途中までの回では更新されません。

## エラー（要対応）の見方と直し方

作品フォルダに不備があると、その作品はギャラリーの一覧に**出ません**。代わりに、一覧の最上部に「**一覧に出ていない作品がN件あります**」というバーが出て、作品ごとに理由が並びます（この文書では「要対応」と呼びます）。各行から「Driveのフォルダ」と「スプシの該当行」へ飛べます。スプシでは `error` 列に同じ内容が入っています（複数あるときは ` / ` でつながります）。

**直し方の基本**：フォルダ名か `meta.json` を直して、ギャラリーの「今すぐ同期」（または詳細の「この作品だけ再同期」）を押す。要対応が0件になれば完了です。

### エラーメッセージ一覧

| メッセージ | 原因 | 直し方 |
| --- | --- | --- |
| フォルダ名が「YYYYMMDD_名前」の形式ではありません | 先頭が8桁の数字＋`_`になっていない | `20250612_流路セルホルダー` の形に改名する |
| フォルダ名の日付「XXXXXXXX」は実在しない日付です | 20250231 など、カレンダーに無い日付 | 実在する日付に直す（不明なら大体でよい） |
| meta.json がありません | フォルダ直下に `meta.json` が無い（サブフォルダの中は不可） | `_template/meta.json` をコピーして置く |
| meta.json が○個あります（1つにしてください） | 同名ファイルが複数ある（Driveは同名を許す） | 余分なものを消す |
| meta.json を読めません（…） | ファイルの読み取りに失敗 | ファイルが開けるか確認し、作り直して置き直す |
| meta.json を JSON として読めません（カンマや " の過不足を確認してください） | JSONの書式エラー | 最後の項目の後ろの余分なカンマ、`"` の閉じ忘れ、全角の `"` を確認する。JSON検証サイトに貼ると場所がわかる |
| meta.json の中身が { } で囲まれていません | 配列や文字列だけが書かれている | 全体を `{ … }` にする |
| meta.json に「author」がありません（purpose / status も同様） | 必須キーが無い | キーを足す |
| 「author」は文字列で書いてください（purpose / status も同様） | 数値や配列などが入っている | `"山田"` のように `" "` で囲む |
| 「author」が空です（purpose / status も同様） | 空文字や空白だけ | 内容を書く。Fusion書き出し直後の雛形はこの状態（**未記入の作品**） |
| 「status」は 使用中 / 参考 / 引退 のどれかにしてください（今は「…」） | 選択肢以外の文字 | 3つのどれかに直す（表記ゆれ・全角半角に注意） |
| 「tags」は文字列の配列で書いてください（例: ["顕微鏡", "治具"]） | `"tags": "顕微鏡"` のように配列でない | `["顕微鏡"]` にする |
| 「note」は文字列か、文字列の配列で書いてください | 数値やオブジェクトが入っている | 文字列、または文字列の配列にする |

`meta.json` を書くときの注意：

- 未知のキーはエラーになりません（無視されます）。
- UTF-8 で保存してください。Windowsのメモ帳が付ける先頭の BOM は自動で除かれます。
- `tags` と `note` は書かなくてもかまいません。

### 画面に出る「同期できませんでした」の類

| 表示 | 原因と対処 |
| --- | --- |
| スクリプトプロパティ「ITEMS_FOLDER_ID」が設定されていません | [SETUP.md の手順5](SETUP.md#5-スクリプトプロパティ-items_folder_id-を設定する) |
| items フォルダ（ID: …）を開けません | IDの誤り、または権限不足 |
| 同期には items フォルダとスプシの編集権限が必要です | 押した人に編集権限が無い。共有ドライブでの役割を見直すか、権限のある人に頼む |
| 同期に失敗しました：… | 想定外のエラー。時間をおいて再実行し、続く場合は改修できる人へ（実行ログはApps Scriptエディタの「実行数」で見られる） |

画像だけ出ない（形のアイコンになる）場合は、閲覧者のDrive権限か、ブラウザのCookie設定が原因のことがあります。動作には影響しません。

## 「全部作り直す」を使う場面

スプシのメニュー「**ギャラリー → 全部作り直す**」は、シートのデータ行を消して、`items/` から全件を読み直します（確認ダイアログが出ます）。普通の同期は変化したフォルダしか読まないので、次のような「シートの状態がおかしい」ときに使います。

- 誰かがスプシを手で編集してしまい、元に戻らない
- シートの行を誤って消した、並べ替えた
- 見出しや列の順番が違っている（`HEADERS` を変えた改修のあとなど）
- 原因不明で、画面とフォルダの内容が合わない

注意：

- 件数が多くて時間切れになると、そこまで読めた分だけがシートに載り、残りは続きの同期（約1分後に自動）で入ります。その間、ギャラリーには一部の作品しか出ません。しばらく待ってください。
- 元データは `items/` なので、作り直しで作品が失われることはありません。

## スプシを手で編集しない理由

スプシは `items/` の**写し**で、同期のたびに上書きされるからです。スプシで直しても、次の同期で消えます。直したい内容は、**各作品フォルダの `meta.json`**（とフォルダ名）を直して同期してください。シートには「警告のみ」の保護がかかっていて、編集しようとすると警告が出ます（同期を止めないため、完全には禁止していません）。

## 管理者交代時の手順

構築者・管理者が卒業するときは、必ず**在籍中に**引き継ぎます。理由：毎日の自動同期の**トリガーは、作った人のアカウントで動く**ため、そのアカウントが無効になると止まります。新しい管理者が作り直す必要があります。旧管理者がまだ在籍しているうちに、次の順で行います。

1. **共有ドライブの管理者に新管理者を追加する**（旧管理者または他の管理者が実施）。`3Dギャラリー/` とスプシ（Apps Script を含む）を編集できる状態にする。
2. **新管理者がスプシを開き、「拡張機能 → Apps Script」が開ける**ことを確認する。
3. **新管理者が `setup()` を実行する**（スプシのメニュー「ギャラリー → 初期設定」、またはエディタで `setup` を実行）。許可画面が出たら許可する。これで**新管理者のアカウントで**毎日の同期トリガーが登録される。結果に「毎日の同期：登録しました」と出ることを確認する。
   - `setup()` は、実行した人のトリガーしか見ません。旧管理者のトリガーが残っていても、新管理者側には新しく登録されます。
4. **旧管理者のトリガーを削除する**。旧管理者が Apps Script エディタ左の時計マーク「トリガー」を開き、`dailySync`（と、残っていれば `continueSync`）を削除する。削除しないと新旧で2本動きます（同期はロックで二重実行が防がれるので壊れはしませんが、無駄です）。旧管理者のアカウントが先に無効になった場合は、そのトリガーも動かなくなるので、この手順は不要です。
5. **デプロイを確認する**。新管理者が「デプロイ → デプロイを管理」で既存のデプロイを開けることを確認する。今後コードを変えるときは、「新しいデプロイ」ではなく**既存のデプロイを編集して「新バージョン」を出す**（URLが変わらない。[SETUP.md](SETUP.md#更新するとき新しいデプロイとデプロイを管理の違い)）。実行ユーザーは「ウェブアプリにアクセスしているユーザー」なので、旧管理者が卒業しても、閲覧する人の権限で動き続けます。
6. **動作確認**：新管理者がスプシのメニュー「今すぐ同期」とギャラリーのURLを確認する。翌日、エディタの「実行数」に、新管理者のアカウントで `dailySync` が走った記録があることを確認する。
7. **置き場所を確認する**：`3Dギャラリー/` が共有ドライブにあること（マイドライブでないこと）、`tools/` の控えが最新であること、[README.md](README.md) のURLが正しいこと。

データ（`items/`、スプシ、コード）が共有ドライブにあれば、管理者が替わっても失われるものはありません。

## Fusion書き出しの運用

Fusionのクラウドにある f3d を、まとめて `items/` 用の作品フォルダとして書き出すスクリプト `tools/fusion_export/fusion_export.py` の使い方です。**卒業でAutodeskアカウントやFusionのライセンスを失うと、クラウド上のf3dに二度とアクセスできなくなるため、在籍中に回収するのが最優先です。**

流れ：**モード1（サムネイルだけ撮って一覧を作る）→ 人が仕分け → モード2（フル書き出し）**。

### 準備

1. `tools/fusion_export/` フォルダ（`fusion_export.py` と `fusion_export.manifest` が入っている）を、手元のPCにコピーする。
2. Fusionを起動し、「ユーティリティ」タブの「**スクリプトとアドイン**」を開く（Shift+S）。「スクリプト」タブの「＋」から、コピーした `fusion_export` フォルダを選んで登録する。
3. 冒頭の「**設定欄**」を書き換える（`fusion_export.py` をエディタで開いて保存すればよい）。

| 設定 | 意味 |
| --- | --- |
| `MODE` | 1 = サムネイルのみ、2 = フル書き出し |
| `OUTPUT_DIR` | モード2の出力先。Google ドライブ（パソコン版）の同期フォルダ内の `3Dギャラリー/items`。**初期値は `G:\マイドライブ\…` だが、共有ドライブに置いた場合は共有ドライブ側のパスに変える**（エクスプローラーでそのフォルダを開いて、アドレスバーのパスを使う） |
| `TRIAGE_DIR` | モード1の出力先。`triage.csv` と画像が入る。`items` の外の作業用フォルダにする |
| `TRIAGE_CSV` | モード2で読む `triage.csv`（仕分け済みのもの）のパス |
| `PROJECT_NAMES` | 対象のFusionプロジェクト名のリスト。`[]` なら全部。**今選んでいるチーム（データパネル左上のハブ）の中だけ**が対象 |
| `STL_PER_BODY` | `True` = ボディごとにSTL（1部品だけ刷り直せる）。`False` = 1ファイルにまとめる |
| `MESH_QUALITY` | `"high"` / `"medium"` / `"low"`（STL・3MFの細かさ） |
| `THUMB_WIDTH` / `THUMB_HEIGHT` | サムネイルの大きさ（初期値 1200×800） |

Windowsのパスは `r"…"` で囲んだままにしてください。設定を保存して、スクリプトを選び「実行」を押します。

実行中の注意：Fusion本体を起動してその中から実行します（裏では動かせません）。1件ずつクラウドから開くので、件数が多いと時間がかかります。進捗ダイアログに「中止」ボタンがあります。実行中は他の操作を控えてください。

### モード1：サムネイルのみ

1. `MODE = 1`、`TRIAGE_DIR`、`PROJECT_NAMES` を設定して実行する。
2. 完了のダイアログに、保存した画像の数・失敗した数・一覧の場所が出る。`TRIAGE_DIR` に次ができる。
   - `triage.csv`：一覧
   - `<フォルダ名案>.png`：サムネイル画像
   - `export_log.csv`：ログ
3. **仕分け**：`triage.csv` をスプシ（Excelでも可）で開き、画像を見ながら `rank` 列に **A / B / C** を書く。必要なら `folder_name`（`YYYYMMDD_名前` の案が最初から入っている）を直す。
   - A：研究室で現役の部品（写真・noteを丁寧に）／B：参考になる過去作／C：失敗作・一発ネタ（登録しない）。**`rank` が A か B の行だけが書き出されます。**
   - `folder_name` の日付が `00000000` の行は、作成日が取れなかったものです。実在する日付に直してください（直さないと同期でエラーになります）。
4. CSVで保存する。スプシなら「ファイル → ダウンロード → カンマ区切りの値（.csv）」。Excelで保存し直した場合（Shift_JIS）も読めます。保存先を `TRIAGE_CSV` に書く。

`triage.csv` の列：`project`（プロジェクト）、`folder_path`、`name`（Fusion上の名前）、`datafile_id`、`version_id`、`created`、`modified`、`image`、`rank`、`folder_name`。

**モード1を再実行すると、既存の `triage.csv` は上書きされず `triage_日時.csv` に退避され、新しい `triage.csv` は `rank` が空になります。** 記入済みのランクを引き継ぎたいときは、退避された側を使ってください。

### モード2：フル書き出し

1. `MODE = 2`、`OUTPUT_DIR`、`TRIAGE_CSV` を設定して実行する。
2. `rank` が A か B の行ごとに、`OUTPUT_DIR/<folder_name>/` を作り、次を書き出す。

   | 出力 | 内容 |
   | --- | --- |
   | `<名前>.f3d` | Fusionの元データ |
   | `<名前>.step` | STEP |
   | `<ボディ名>.stl` | ボディごと（`STL_PER_BODY = True` の場合。名前が重なれば `_2` など） |
   | `<名前>.3mf` | 3MF |
   | `thumb.png` | ギャラリーの代表画像 |
   | `meta.json` | 雛形（`author` `purpose` `status` は空） |

   `OUTPUT_DIR` がDriveの `items/` なら、書き出し＝登録です。
3. 完了ダイアログに、成功・成功（要目視確認）・失敗・スキップの件数とログの場所が出る。
4. 各作品の `meta.json` を埋める（手で、または [AI_GUIDE.md](AI_GUIDE.md) の方法）。雛形の `note` には「Fusion元: プロジェクト/フォルダ/名前」が入っているので、残しておくと元データをたどれます。
5. ギャラリーの「今すぐ同期」を押す。`meta.json` が空の作品は「`author` が空です」などで要対応に出ます（**未記入の作品**）。要対応が0件になれば完了です。

### `export_log.csv` の見方

モード1は `TRIAGE_DIR` に、モード2は `OUTPUT_DIR`（`items/` の直下）に作られます。`items/` 直下のファイルは同期の対象ではない（同期が読むのはフォルダだけ）ので、置いたままで問題ありません。1件ごとに追記され、途中でFusionが落ちてもそこまでは残ります。列は `time, mode, name, result, detail` です。

| result | 意味 | 対応 |
| --- | --- | --- |
| 成功 | 書き出し完了（`meta.json` まで書けた） | `detail` の「取得: version_id」などは、ファイルをどのIDで見つけたかの記録。通常は気にしなくてよい |
| 成功（要目視確認） | 書き出せたが、**外部参照を含む**デザイン（他のデザインを参照するアセンブリ）。`detail` に「外部参照あり」 | f3d・STEP・STLの中身を目視で確認する。参照先が欠けていないか |
| 失敗 | 開けない、書き出し形式のどれかが失敗、など。`detail` に原因 | 原因を直して再実行（下記）。その作品フォルダには `meta.json` が書かれない |
| スキップ | `meta.json` があるので書き出し済みとして飛ばした | 何もしなくてよい |
| 注意 | `triage.csv` の `folder_name` に問題（重複を `-v2` などに変更した、形式外の名前）。作品名の欄は空 | 該当の `folder_name` を直す |

`detail` には「表示中のソリッドボディが無いため STL/3MF なし」のような補足も入ります。モード1のログは、画像を保存できたか（成功）か、開けなかった（失敗）かを記録します。

### 再実行の挙動

- **`meta.json` があるフォルダは、書き出し済みとして飛ばします**。`meta.json` は全部の書き出しが成功したときに**最後に**書くので、途中で止まったフォルダ（`meta.json` が無い）は次の実行でやり直されます。
- 失敗した作品は、原因を直して**そのままモード2をもう一度実行**すれば、失敗分だけやり直します。
- 書き出し済みの作品を書き出し直したいときは、その作品フォルダ（または `meta.json`）を削除してから再実行します。`meta.json` を埋めたあとに消すと記入内容も失われるので注意してください。
- 同じ `folder_name` が複数あると、2つ目以降に `-v2`、`-v3` を付けます（CSVの行順で振るので、同じCSVなら再実行しても同じ名前になります）。
- 書き出し途中の `items/` では、`meta.json` がまだ無いフォルダが「meta.json がありません」と要対応に出ます。実行が終われば解消します。

### うまくいかないとき

- 開けない・書き出せない作品は、手動（Fusionで開いて「ファイル → エクスポート」）で補い、ギャラリーの「作品を追加する」の手順で置いてください。
- Fusionのバージョンアップでスクリプトが動かなくなることがあります。確認済みのバージョンは [DEVELOPMENT.md](DEVELOPMENT.md#確認したfusionのバージョン) にあります。STEPが残っていれば、Fusionが無くても他のCADで形を取り戻せます。
