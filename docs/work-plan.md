# 3Dプリント作品ギャラリー 作業計画

2026-10-30 作成。設計の正は `docs/plan.md`（計画書）と `docs/gallery_mock.html`（画面モック）。この文書は「それをどう作るか」と、計画書に書かれていない細部の決定を記録する。セッションをまたぐときは末尾の「進捗」を更新する。

## 背景・目的

研究室の3Dプリント作品を、後輩が「これ何？」「また刷りたい」「ちょっと変えたい」に自力で答えられる形でGoogleドライブに残す。作品フォルダ（meta.json）が唯一の正で、スプシとギャラリーは派生物。詳細は計画書。

## 役割分担

- こちら（Claude）: コード・テンプレート・ドキュメントを作り、ローカルで検証できるところまで検証する
- ユーザー: GASへの貼り付けとデプロイ、Fusion上での実行。完成後にまとめて引き継ぐ（Fusionスクリプトも途中で渡さない）

## 決定事項（2026-10-30 確認済み）

- Webアプリの実行ユーザーは計画どおり「ウェブアプリにアクセスしているユーザー」。閲覧者にも初回にDriveの許可画面が出ることを README と SETUP に書く
- 引き渡しは一通り完成してから1回

## 範囲

### 「この流れができていれば良い」（ユースケース）

1. **回収**: Fusionでモード1 → `triage.csv` にランクとフォルダ名を記入 → モード2で `items/` に作品フォルダが並ぶ（meta.json は未記入）
2. **記入**: AIプロンプトか手で meta.json を埋める → ギャラリーの「要対応」が減っていく
3. **閲覧**: 後輩がギャラリーを開き、絞り込み → 詳細 → STL をダウンロード / f3d を開く
4. **手動登録**: `_template` をコピーして1件追加 → 「今すぐ同期」で表示される
5. **管理**: 毎日の自動同期、エラー対応、管理者交代

### やらないこと

計画書の「スコープ外」に加えて：clasp などのデプロイ自動化（コピペ前提を守る）、GAS拡張サービス、外部JSライブラリ、ギャラリーからの編集・アップロード。

## 計画書の隙間を埋める決定（実装方針）

ここに書いたものは仮決定。実装中に変える場合はここを更新する。

### 同期（Code.gs）

- **フォルダ名**: `^(\d{8})_(.+)$`。日付は実在する日付か検査する。`-v2` などは名前の一部として扱う
- **対象外**: 先頭 `_` のフォルダ、ゴミ箱の中のもの（`isTrashed()` で明示的に除く）、ショートカット
- **meta.json の検査**（不備は error 欄に日本語で記録し、ギャラリーの「要対応」に出す）
  - 無い / 同名が複数ある（Driveは同名ファイルを許すため）/ JSONとして読めない（先頭の BOM は除去してから読む）
  - 必須3キーが無い・空 / `status` が選択肢外 / `tags` が文字列の配列でない / `note` が文字列でも文字列の配列でもない
  - 未知のキーはエラーにしない（将来キーを足したときに古いコードで壊れないように）
  - 状態の選択肢は Code.gs 冒頭の定数1か所（未決事項「3つで足りるか」に後から対応しやすく）
- **代表画像**: `thumb.png` → `thumb.jpg` → `thumb.jpeg` → 名前順で最初の画像
- **fingerprint**: フォルダ名＋各ファイルの「名前・サイズ・更新日時」を名前順に並べて SHA-256。フォルダ名を含めるのは、リネームだけでは中身が変わらないため
- **書き込み**: シートを1回で読み、メモリ上で更新して、区切りごとにまとめて書く（1行ずつ書くと遅い）
- **時間切れ対策**: 名前順に処理し、約4.5分で区切る。続きの位置をスクリプトプロパティに保存し、1回限りのトリガー（1分後、実行後に自分を削除）で再開。消えたフォルダの行の削除は、全件を見終えた回だけ行う
  - Webの「今すぐ同期」は続きのトリガーを作らず、「途中まで同期しました。もう一度押すと続きから」と返す（閲覧者のアカウントにトリガーが残らないように）
- **二重実行**: `LockService.getScriptLock()`。取れなければ「別の同期が実行中」と返す
- **手編集の抑止**: シートに「警告のみ」の保護をかけ、見出しにメモ「編集は meta.json で」。完全な保護にすると、編集権限のある人の同期まで止まるため
- **権限**: 「今すぐ同期」の失敗は「同期には items フォルダとスプシの編集権限が必要です」と言い換えて表示
- **メニュー**（`onOpen`）: ギャラリー → 今すぐ同期 / 全部作り直す（シートを空にして再同期）/ 初期設定
- **`setup()`**: 見出し・保護・時間トリガー（重複登録しない）・`ITEMS_FOLDER_ID` の存在確認

### ギャラリー（index.html / guide.html）

- モックをそのまま移植し、`SAMPLE_DATA` を削除。GASとの境目はモックどおり `loadData` / `syncNow` / `resyncItem` の3関数
- URL: 画像は `https://drive.google.com/thumbnail?id=<id>&sz=w600`、ファイルは `/file/d/<id>/view`、ダウンロードは `uc?export=download&id=<id>`
- 画像が読めないとき（権限やブラウザのCookie制限）は `onerror` で形のアイコンに差し替える。形と色はフォルダIDから決めて、作品ごとに見分けがつくようにする
- AIプロンプトは計画書の版（モックより詳しい）に揃え、`guide.html` 内の1か所に置く
- 「要対応」の各行から、Driveのフォルダとスプシの該当行へ飛べるようにする

### Fusion書き出し（fusion_export.py）

- モード1の `triage.csv` には、空の `rank` 列と、作成日から作った `folder_name` 案（`YYYYMMDD_名前`）を最初から入れておく。仕分けはランクを書いて、必要ならフォルダ名を直すだけで済む
- CSV は BOM 付き UTF-8 で書き、読むときは BOM の有無どちらも受ける（Excel で開いても化けない）
- 完了の目印として **meta.json を最後に書く**。meta.json のあるフォルダは再実行時に飛ばし、途中で止まったフォルダはやり直す
- meta.json の雛形の `note` に「Fusion元: プロジェクト/フォルダ/名前」を入れる（後から元データをたどれるように）
- STL はルートと全オカレンスの表示中ソリッドボディを対象にする。ボディ名の重複は `_2` などで回避。1ファイルにまとめる設定も用意
- 進捗ダイアログ（キャンセル可）と `adsk.doEvents()`、1件ごとの try/except と `export_log.csv`
- Fusion を要しない部分（CSV、命名、スキップ判定）は関数に分け、`dev/fusion-test` で検証する

## 第2ラウンド（2026-10-30、実機確認の結果を受けて）

### 実機確認の結果

- D1 は採用（`appsscript.json` を使う）、D2 は大学ドメイン内でよい。D3 は**全員を編集者にする**（管理者が誰になるか、権限の設定を今後も保守できるかが分からないため）
- C1・C2・C4・C6〜C9 は問題なし。C5 は未確認（全員が編集者なら、閲覧者だけの場面はなくなる）
- **C3: PC では画像が出るが、スマホでは出ない** → 想定していた Cookie 制限（スマホのブラウザは iframe 内で drive.google.com の Cookie を送らない）とみる
- F1・F2 は問題なし。F3 はおおむね問題なし（件数が多く、全部は見ていない）
- **F4: 外部参照を含むデザインの f3d を開くと中身が空だった**（STEP/STL は出ていた。ユーザー回答） → API の Fusion アーカイブ書き出しは参照先を含まない。Autodesk のフォーラムでも、参照先を含む本物の f3z は API では作れないと回答されている
- F5 は保留（済み判定の仕組みについて質問あり）。F6: Fusion 2705.1.15

### 対応（R = 第2ラウンドの項目）

| # | 内容 | 方針 |
| --- | --- | --- |
| R1 | スマホでサムネイルが出ない | まず今どおり Drive の URL で読み、失敗した画像だけ、サーバー（`getThumbnails(ids)`）に頼む。サーバーは `DriveApp.getFileById(id).getThumbnail()` で縮小画像を取り、data URL で返す（数件ずつまとめて呼ぶ。CacheService で6時間保存）。新しい権限は要らない。PC は今までどおり速い。縮小画像は幅220px程度で、カードには足りるが詳細の大きな画像では粗い。そのため詳細の画像だけは、2MB 以下なら元のファイル（`getBlob()`）を返す |
| R2 | リストの行ががたつく | 行を [画像][名前・用途（伸びる）][タグ（右寄せ・折り返し）][状態（固定幅）][日付（固定幅）] にする。右側の位置がそろう。スマホ幅ではタグを名前の下に回す |
| R3 | リスト表示でスクロールできない | 原因は CSS。`.main` は縦並びの flex で、`.list` に `overflow:hidden` があるため、`.list` が親の高さまで縮められて下が切れる（作品数が少ないプレビューでは気づけなかった）。`.list` が縮まないようにする。作品30件のプレビューを作り、PC とスマホの幅で最下部まで見えるかをスクショで確かめる |
| R4 | 一覧のタグを押して絞り込む機能は要らない。ホバーで色が変わらない | カードとリストのタグはただの文字にする（押せない。ホバーの見た目もなし）。カード全体（タグの部分も含む）を押すと、その作品を選ぶ。詳細ペインのタグは絞り込みに使えるまま残し、ホバーではっきり色が変わるようにする。左の絞り込み欄のタグは今のまま |
| R5 | 外部参照のある f3d が空 | 自分で開いたドキュメントに限り、参照している配置を `Occurrence.breakLink()` で取り込み（入れ子は無くなるまで繰り返す）、それから f3d を書き出す。保存はしない（`close(False)`）ので、クラウド上の元データは変わらない。もともと開いていたドキュメントは書き換えないので、従来どおり「要目視確認」とする |
| R6 | Fusion元を note に入れない。済み判定の仕組み | note には何も入れない（空の配列）。代わりに meta.json の専用キー `fusion_id`（DataFile の ID。版や名前、置き場所が変わっても同じ）に入れる。未知のキーは同期でもギャラリーでも無視されるので、画面には出ない。判定は「meta.json あり、かつ `fusion_id` が一致 → 済み」「`fusion_id` が違う → 別の作品なので -v2 に書く」「`fusion_id` が無い（手で消した、手作りの同名フォルダ、旧版の出力）→ 念のため済み扱いでスキップし、ログに理由を書く」。重複して書き出すよりも、飛ばしたほうが害が少ないため。旧版の「Fusion元」行がある場合は、それとも照合する。AIプロンプトと _template の README に「`fusion_id` は消さない」と書く |
| R7 | 設定欄の整理 | 「共通 → モード1だけ → モード2だけ → 細かい設定」の順に並べ替える。モード1の出力先は既定を `ドキュメント\3Dギャラリー_仕分け`（ローカル）にする。`TRIAGE_CSV` は空なら `TRIAGE_DIR\triage.csv` を使う。Googleドライブ上でなければならないのはモード2の `OUTPUT_DIR` だけ |

| E5 | サーバー | `updateItemMeta(folderId, fields, baseFingerprint)`：meta.json を読み、画面から来た項目だけを差し替え、**知らないキー（`fusion_id` など）はそのまま残す**。書き込みは `setContent`（ファイル ID が変わらない）。`baseFingerprint` が今の行の指紋と違えば、書かずに「ほかの人が先に変更しました」を返し、画面は最新を読み直して下書きを当て直す。`trashItemFile(folderId, fileId)`：ファイルがその作品フォルダの直下にあり、`meta.json` でないことを確かめてから、ゴミ箱へ。どちらも最後に `resyncItem_` を呼び、新しい item を返す（画面はそれで差し替え、全件を読み直さない）。対象のフォルダが items の直下であることは、今の `isDirectChildOf_` で毎回確かめる。値の検査は `checkMeta` を使う（画面でも同じ規則で先に知らせるが、正はサーバー） |
| E6 | 要対応を画面で直す | 要対応の行のうち、meta.json の中身の不備（必須が空・状態が選択肢外・meta.json が無い）は、行の「画面で直す」から E1 と同じフォームで直せるようにする。Fusion から書き出した直後の作品（meta.json が空のまま並ぶ）を、AI に頼まずにその場で埋められる。JSON として壊れているものは、元の文字列を見せたうえで上書きを確かめる。フォルダ名の不備（日付が無いなど）は段階 D まで今の案内のまま |
