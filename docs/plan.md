# 3Dプリント作品ギャラリー 計画書

Oct 29, 2026 · @Nu424

## 目的とスコープ

研究室でこれまでに3Dプリンターで作ったものを、**後輩が「これ何？」「また刷りたい」「ちょっと変えたい」に自力で答えられる形**で研究室のGoogleドライブに残す。卒業者が今後も作品を置いていける仕組みにする。

後輩のニーズと、それに答えるデータの対応は次のとおり。

| 後輩のニーズ | 必要なもの |
| --- | --- |
| これ何？（用途・状態を知りたい） | 写真、用途、状態、備考 |
| また刷りたい | STL / 3MF |
| ちょっと変えたい | f3d（Fusion）、STEP（Fusion以外でも開ける保険） |

**設計方針**

- 作品フォルダ（meta.json を含む）が唯一の正。スプシとギャラリーはそこから作る派生物で、壊れても作り直せる
- 登録は「Driveの所定フォルダに作品フォルダを置く」だけ。アップロード画面は作らない
- 構成は最小限。GASは「.gs と .html をコピペ＋スクリプトプロパティ設定」で動く
- 改修や登録をAIエージェントに頼めるよう、指示の出し方もドキュメントに含める

**スコープ外**：プリンター・材料・印刷設定・印刷時間の記録（研究室でほぼ共通のため）、現物の保管場所、外部から取得したモデルの配置、ギャラリー上での3Dプレビュー。

作品はFusionからのスクリプト書き出しか手動で `items/` に入る。同期がそれをスプシに写し、ギャラリーはスプシだけを読む。正は `items/` だけなので、スプシとギャラリーは壊れても作り直せる。

## データ仕様

1作品＝1フォルダ、中身はフラット。日付と名前はフォルダ名から取るので、meta.json には書かない。

### フォルダ配置と命名

```
3Dギャラリー/
└── items/
    ├── 20250612_流路セルホルダー/
    ├── 20250903_ステージ用スペーサー/
    └── _template/          ← 先頭が _ のフォルダは同期対象外
```

- 形式は `YYYYMMDD_名前`。日付は**モデルの作成日**（不明なら大体でよい。登録日ではない）
- 名前は日本語可。`/` `\` `:` などファイル名に使えない記号は避ける
- 同じ日付・同じ名前が重なったら末尾に `-v2` などを付ける
- 先頭が `_` のフォルダ（テンプレート、退避用など）は同期で無視する

### フォルダの中身

| ファイル | 要否 | 内容 |
| --- | --- | --- |
| `meta.json` | 必須 | 作品情報（下記） |
| `thumb.png` または `thumb.jpg` | 推奨 | ギャラリーの代表画像。無ければフォルダ内の最初の画像を使う |
| `*.f3d` | 推奨 | Fusionの元データ。編集用の正本 |
| `*.step` | 推奨 | Fusion以外のCADでも開ける保険。履歴（スケッチ・寸法拘束）は消える |
| `*.stl` / `*.3mf` | 推奨 | 印刷用。部品が複数なら `base.stl`, `lid.stl` のように並べる |
| `photo_*.jpg` / `photo_*.png` | 任意 | 使用中の様子、スケール入りの写真など |
| その他 | 任意 | 図面PDFなど。ギャラリーにはファイル一覧として表示する |

### meta.json

| キー | 要否 | 型 | 内容 |
| --- | --- | --- | --- |
| `author` | 必須 | 文字列 | 作った人 |
| `purpose` | 必須 | 文字列 | 何のための部品か（一行） |
| `status` | 必須 | 文字列 | `使用中` / `参考` / `引退` のいずれか |
| `tags` | 任意 | 文字列の配列 | 絞り込み用（装置名、種類など） |
| `note` | 任意 | 文字列、または文字列の配列 | 上記以外すべて。配列なら1要素＝1行として表示 |

絞り込み・並び替えに使う情報だけを項目にし、それ以外は `note` に寄せる。`note` を配列でも書けるようにしているのは、手書きで改行 `\n` を打つ手間を省くため。

```json
{
  "author": "山田",
  "purpose": "流路セルを顕微鏡ステージに固定する",
  "status": "使用中",
  "tags": ["顕微鏡", "治具"],
  "note": [
    "M3ネジ×4で固定。",
    "縦向きで刷らないと爪が折れる。",
    "v2で穴径を0.2mm拡大。"
  ]
}
```

フォルダ名が形式に合わない、meta.json が無い・壊れている、必須キーが欠けている場合、その作品はギャラリーに出さず、スプシのエラー欄に理由を記録する。

## Fusion書き出しスクリプト

FusionのPython APIで、クラウド上のf3dを開いて書き出すところまで自動化できる。RPAやComputer Useは使わない。必要なAPIは公式に揃っている：STEP・STL・3MF・f3dの書き出しは `ExportManager`（[ExportManager](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/ExportManager.htm)、[FusionArchiveExportOptions](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/FusionArchiveExportOptions.htm)）、サムネイルは画面を指定サイズで再描画して保存する `Viewport.saveAsImageFile`（[Viewport.saveAsImageFile](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/Viewport_saveAsImageFile.htm)）、クラウドのファイルは `DataFile` を `Documents.open` で開く。

**ファイル**：`fusion_export/fusion_export.py` 1本。冒頭の設定欄（出力先、モード、対象プロジェクト）を書き換えて、Fusionの「スクリプトとアドイン」から実行する。

### モード1：サムネイルのみ（トリアージ用）

1. 対象プロジェクト配下のフォルダを再帰的にたどり、f3dのDataFileを列挙する
2. 1件ずつ開き、全体表示・斜め視点にしてPNGを保存し、保存せずに閉じる
3. 一覧を `triage.csv` に書く。列：プロジェクト、フォルダパス、名前、DataFileのID、作成日、最終更新日、画像ファイル名

`triage.csv` と画像をDriveに上げてスプシで開き、「ランク（A/B/C）」と「フォルダ名」の列を足して仕分ける。

### モード2：フル書き出し（A・Bランク）

仕分け済みの `triage.csv`（ランクA・Bの行、フォルダ名入り）を読み、1件ごとに作品フォルダを作る。

| 出力 | 方法 |
| --- | --- |
| `<名前>.f3d` | FusionArchive書き出し |
| `<名前>.step` | STEP書き出し |
| `<ボディ名>.stl` | ボディごとにSTL書き出し。1部品だけ刷り直せて、スライサーでも別々に置ける（1ファイルにまとめる出力は設定で切替） |
| `<名前>.3mf` | 3MF書き出し |
| `thumb.png` | ビューポート画像 |
| `meta.json` | 雛形。`author` などの必須値は空のまま出す |

フォルダ名の日付は、仕分け時に入力が無ければDataFileの作成日を使う。必須値が空の meta.json は同期でエラー扱いになるので、記入漏れがスプシ上で「未記入の作品」として見える。

出力先をGoogleドライブ（パソコン版）の同期フォルダ内の `items/` にすれば、書き出し＝登録になる。

### 制約と注意

- Fusion本体を起動した状態で、その中から実行する。裏で動かす仕組みは無い
- 1件ごとにクラウドからの読み込みが入るので、件数が多いと時間がかかる。実行中は `adsk.doEvents()` で画面を固めない
- 1件の失敗で止めず、ログ（`export_log.csv`）に記録して次へ進む。再実行時は出力済みの作品を飛ばす
- 他のデザインを参照している（外部コンポーネントを含む）アセンブリは、書き出し結果を目視で確認する
- APIはFusionの更新で変わることがある。動作確認したFusionのバージョンをドキュメントに残す

## GAS同期処理

`items/` の作品フォルダを読み、スプシ（インデックス）を作品フォルダの写しに保つ。スプシは手で編集しない前提で、壊れたら全消しして再同期すれば戻る。

### GASプロジェクトの置き場所

インデックス用スプシの「拡張機能 → Apps Script」に置く（コンテナバインド）。スプシのメニューから同期を呼べて、設定するIDが1つ減る。スクリプトプロパティは `ITEMS_FOLDER_ID`（`items/` フォルダのID）の1つだけ。

### スプシの列（シート名 `items`）

| 列 | 内容 |
| --- | --- |
| `folder_id` | 作品フォルダのID（行の主キー） |
| `folder_name` | フォルダ名そのまま |
| `date` / `name` | フォルダ名から分解した日付と名前 |
| `author` / `purpose` / `status` | meta.json から |
| `tags` | カンマ区切り |
| `note` | 改行区切りの文字列 |
| `thumb_id` | 代表画像のファイルID |
| `files` | フォルダ内ファイルの一覧（名前・ID・サイズのJSON） |
| `fingerprint` | フォルダ内ファイルの名前・サイズ・更新日時から作るハッシュ |
| `error` | 不備の内容。空ならギャラリーに表示 |
| `synced_at` | 最終同期日時 |

### 同期の流れ

1. `items/` 直下のフォルダを列挙（先頭 `_` は除外）
2. 各フォルダのファイル一覧を取り、`fingerprint` を計算
3. スプシの値と同じなら何もしない。違えば meta.json を読み直して行を更新
4. スプシにあってDriveから消えたフォルダの行は削除する

差分判定に使うのはフォルダ内のファイル一覧なので、写真を1枚足しただけでも拾える。フォルダの最終更新日時は中身の変更で更新されないことがあるため使わない。

### 実行のきっかけ

- 時間トリガー：1日1回の全体同期
- スプシのメニュー「ギャラリー → 今すぐ同期」
- ギャラリー画面の「今すぐ同期」ボタン、詳細画面の「この作品だけ再同期」ボタン

### 制限への対策

- GASの1回の実行時間上限（6分）に備え、処理済みの位置をスクリプトプロパティに保存し、時間切れが近づいたら続きを1分後のトリガーで再開する
- `LockService` で同期の二重実行を防ぐ
- 想定規模（数十〜百数十件）なら全フォルダ走査で収まる見込み。実測して遅ければ、`DriveApp.searchFiles` で最近更新されたファイルだけを拾う方式に切り替える

### 初期化

`setup()` を1回実行すると、シートの見出し作成、時間トリガーの登録、メニューの追加を行う。

## ギャラリーWebアプリ

スプシを読んで表示するだけの閲覧用Webアプリ。Driveを直接走査しないので開くのが速い。

### ファイル構成

| ファイル | 役割 |
| --- | --- |
| `Code.gs` | 同期処理、`doGet`、画面から呼ぶ関数（一覧取得、再同期） |
| `index.html` | 一覧と詳細の画面。見た目とブラウザ側の処理はすべてここ |
| `guide.html` | 「登録のしかた」の本文。文章の修正はこのファイルだけで済む |

`index.html` から `guide.html` を読み込む。3ファイルとも外部ライブラリは使わない。

### 画面

デザインは `gallery_mock.html`（Claude Code への申し送り用モック）を正とする。棚やビルドプレートのような比喩は使わず、使いやすさで勝負する。

**レイアウト**：1画面で完結させる。高さは100svhで固定し、3つのパネルがそれぞれ単体でスクロールする。960px未満では固定をやめて縦に積む。

| パネル | 中身 |
| --- | --- |
| 左：絞り込み（たためる） | キーワード、状態（件数つき）、タグ（件数つき）、作った人。たたむと、効いている絞り込みの数をバッジで出す |
| 中央：一覧 | 要対応バー（最上部）、件数と効いている絞り込み（×で個別に解除）、並び順（新しい順・名前順）と表示切替（ギャラリー・リスト）、作品 |
| 右：詳細（幅440px固定） | 状態と作成日、名前、用途、タグ、画像と写真、メモ、ファイル（編集用・印刷用・画像）、作った人とフォルダ（フォルダ名の下に「Driveで開く」）、この作品だけ再同期 |

- ギャラリーのカード：画像と状態ラベル、名前、用途（2行まで）、タグ、作成日（薄く）
- リストの行：小さい画像、名前と用途、状態、作成日、タグ
- タグはどこで押してもそのタグで絞り込む。もう一度押すと解除
- 状態の色：使用中＝黄、参考＝白、引退＝グレー
- 「作品を追加する」は右から出るパネルで、中身は次章（`guide.html`）

画像は thumb があればDriveのサムネイルを表示し、無ければ形のアイコンで代用する。研究室のDriveに閲覧権限がある人ならそのまま見える。

### デプロイ設定

- 実行ユーザー：**ウェブアプリにアクセスしているユーザー**。Driveとスプシの閲覧権限がそのまま効き、デプロイした人が卒業しても権限の持ち主が消えない
- アクセスできるユーザー：研究室のドメイン内、または研究室メンバー
- 「今すぐ同期」はスプシとフォルダの編集権限がある人だけが実行できる

### 置き場所の前提

`3Dギャラリー/` フォルダ一式は**共有ドライブ**に置く。マイドライブに置くと、持ち主のアカウントが卒業で削除されたときに一緒に消える。

## 「作品を追加する」パネル

パネルの冒頭で「完成形」を見せ、そこへの道を**手動**と**自動**の2本示す。どちらでも最後は `items/` にフォルダを置くだけで、同じ形になればよい。

### パネルの構成

1. **完成形**：フォルダ構成図、meta.json の例、必須項目の表（データ仕様の章と同じ内容）
2. **どちらのやり方にするか**：1〜数件なら手動、それ以上やFusionのプロジェクト丸ごとなら自動
3. **手動のやり方**
4. **自動のやり方**
5. **AIに手伝ってもらう**：コピーボタン付きのプロンプト
6. **置いたあと**：同期のしかた、エラーが出たときの見方

### 手動のやり方

1. `items/_template/` をコピーし、`YYYYMMDD_名前` にリネームする
2. Fusionでデザインを開き、「ファイル → エクスポート」で `.f3d` と `.step` を保存する
3. 印刷用に `.stl` か `.3mf` を保存する（ボディを右クリック →「メッシュとして保存」でもよい）
4. 見栄えのよい角度で画面をキャプチャし、`thumb.png` として保存する
5. `meta.json` の `author` `purpose` `status` を埋める。書ききれないことは `note` に
6. フォルダを `items/` に置き、ギャラリーで「今すぐ同期」を押して表示を確認する

`_template/` には空欄の meta.json と、この手順を書いた `README.txt` を入れておく（README.txt はギャラリーのファイル一覧に出るだけで害はない）。

### 自動のやり方

1. `tools/fusion_export/fusion_export.py` をFusionの「スクリプトとアドイン」に登録する
2. 設定欄で対象プロジェクトと出力先を指定し、モード1（サムネイルのみ）で実行する
3. 出てきた `triage.csv` をスプシで開き、A/B/C とフォルダ名を記入する
4. モード2（フル書き出し）で実行する。出力先が `items/` ならここで登録まで終わる
5. 各フォルダの meta.json を埋める（次節のAIプロンプトを使うと楽）
6. ギャラリーの「要対応」が0件になれば完了

### AIに手伝ってもらうプロンプト

ファイルの仕分けと meta.json 作成をAIエージェントに任せる用。STEPやSTLの書き出しはFusionが要るので、AIに渡す前に手動かスクリプトで済ませておく。

```markdown
あなたは研究室の3Dプリント作品ギャラリーへの登録を手伝います。
渡したファイル（またはフォルダ）から、下の仕様どおりの作品フォルダを作ってください。

## 仕様
- 1作品＝1フォルダ。フォルダ名は YYYYMMDD_名前（日付はモデルの作成日）
- フォルダ内はサブフォルダを作らずフラットに置く
- 代表画像は thumb.png または thumb.jpg、追加写真は photo_ で始める
- 印刷用STLは部品ごとに分ける（base.stl, lid.stl など）
- meta.json のキーは author, purpose, status, tags, note の5つだけ
  - status は「使用中」「参考」「引退」のいずれか
  - note は文字列の配列（1要素＝1行）

## 進め方
1. ファイルを見て作品ごとにまとめる。どれが同じ作品か迷ったら聞く
2. 作成日・名前・作者・用途・状態を、全作品分まとめて一度に質問する。
   ファイル名や更新日から推測できるものは案として示す
3. フォルダ名を決めてファイルを配置し、meta.json を書く。仕様外の情報は note へ
4. 最後にフォルダ構成と各 meta.json を一覧で見せて、確認をもらう

## やらないこと
- モデルの形状やファイルの中身の変更
- 仕様にないキーやフォルダの追加
```

ページ上ではこのプロンプトの仕様部分を `guide.html` 内の一か所にまとめ、仕様を変えたときの修正漏れを防ぐ。

## ドキュメント整備

ドキュメントとコードの控えは `3Dギャラリー/tools/` に置き、Markdownで書く。人もAIもそのまま読めるから。

```
3Dギャラリー/
├── items/
├── index（スプシ。GASはここに入っている）
└── tools/
    ├── gas/            ← Code.gs, index.html, guide.html の控え
    ├── fusion_export/  ← fusion_export.py
    └── docs/
        ├── README.md
        ├── SETUP.md
        ├── OPERATION.md
        ├── DEVELOPMENT.md
        └── AI_GUIDE.md
```

| ファイル | 読む人 | 内容 |
| --- | --- | --- |
| `README.md` | 全員 | 何のための仕組みか、どこに何があるか、ギャラリーのURL |
| `SETUP.md` | 構築する人 | 共有ドライブとスプシの用意、コードの貼り付け、スクリプトプロパティ、`setup()`、デプロイと権限 |
| `OPERATION.md` | 管理者 | 同期のしかた、エラーの直し方、**管理者交代時の手順**（トリガーの張り直し、再デプロイ） |
| `DEVELOPMENT.md` | 改修する人 | 3ファイルの役割と主な関数、データ仕様を変えるときに直す箇所の一覧、動作確認の手順、確認したFusionのバージョン |
| `AI_GUIDE.md` | AIに改修を頼む人 | 下記 |

### AI\_GUIDE.md に書くこと

**AIに渡すもの**

- `DEVELOPMENT.md` と、直したいファイルの全文
- データ仕様（`DEVELOPMENT.md` 内）
- 何を変えたいか、なぜか（「タグで複数選択して絞り込みたい」など、画面上の振る舞いで書く）

**守ってもらう制約**（依頼文に毎回貼る）

- `Code.gs` / `index.html` / `guide.html` の3ファイル構成を変えない
- 外部ライブラリやGASの拡張サービスを追加しない
- meta.json の既存キーの意味を変えない。キーを足すなら任意項目にし、古い作品が壊れないようにする
- 変更点と、`DEVELOPMENT.md` のどこを更新すべきかを最後に一覧で出す

**受け取ったあとの確認**

- スプシごとコピーしたテスト環境で、`ITEMS_FOLDER_ID` をテスト用フォルダに向けて同期を試す
- 「デプロイをテスト」のURLで画面を確認してから本番デプロイを更新する
- `tools/gas/` の控えを差し替え、`DEVELOPMENT.md` を更新する

フェーズ1を最優先にするのは、卒業でFusionのアカウントを失うと元データを取り戻せないから。ギャラリーが未完成でも、`items/` にファイルが揃っていれば引き継ぎとしては成立する。

**既存データの仕分け基準**

| ランク | 対象 | 扱い |
| --- | --- | --- |
| A | 研究室で現役の部品 | フル書き出し＋写真＋note を丁寧に |
| B | 参考になる過去作 | フル書き出し＋note は一言 |
| C | 失敗作、一発ネタ | 登録しない。Fusionのクラウドに残すか削除する |

## 未決事項とリスク

### 未決事項

- [ ] 研究室で共有ドライブを使えるか、`3Dギャラリー/` の管理者を誰にするか
- [ ] Webアプリを見られる範囲（大学ドメイン内か、研究室メンバー限定か）
- [ ] Fusionのクラウドにあるプロジェクトと、f3dのおおよその件数（モード1の所要時間の見積もりに使う）
- [ ] 状態の選択肢は「使用中 / 参考 / 引退」の3つで足りるか

### リスク

| リスク | 起きること | 対策 |
| --- | --- | --- |
| 卒業後にAutodeskアカウントやFusionのライセンスが使えなくなる | クラウド上のf3dに二度とアクセスできない | **在籍中に**モード2でf3dをDriveへ回収する。この計画で最優先 |
| 構築者の卒業 | 時間トリガーが止まる、デプロイを更新できない | 共有ドライブに置く、実行ユーザーを「アクセスしているユーザー」にする、`OPERATION.md` に交代手順を書く |
| Fusion APIの仕様変更 | 書き出しスクリプトが動かなくなる | 確認したバージョンを記録する。STEPを残しておけばFusion無しでも使える |
| meta.json の未記入が放置される | ギャラリーに出ない作品が溜まる | 一覧上部の「要対応 N件」で見えるようにする |
| 作品数が増えて同期が6分を超える | 同期が途中で止まる | 続きから再開する仕組みを最初から入れる。遅ければ差分検索に切り替える |
| スプシを手で編集される | 次の同期で上書きされる | スプシ冒頭とドキュメントに「編集はmeta.jsonで」と明記し、シートを保護する |
